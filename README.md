# core. — платформа для залов (MVP)

Веб-кабинет, в котором небольшой зал ведёт клиентов, абонементы, посещения и расписание и видит клиентов
«в зоне риска». Все данные хранятся в одной базе и отдаются через API, поэтому iOS-приложение core.
подключается к тому же бэкенду без переделки кабинета.

| Часть | Где | Стек |
|---|---|---|
| База, права, бизнес-логика | `supabase/migrations` | PostgreSQL 15, RLS, функции `security definer`, pg_cron |
| API для приложения, ЮKassa, уведомления | `supabase/functions` | Supabase Edge Functions (Deno) |
| Кабинет зала | `web` | Next.js 16 + TypeScript, Tailwind, компоненты в стиле shadcn/ui (Radix) |
| Self-hosted Supabase для серверов в РФ | `deploy` | Docker Compose: Postgres, Auth, REST, Realtime, Functions, Kong |
| Документация | `docs` | OpenAPI для приложения, подключение iOS, развёртывание |

## Демо-ссылка за 10 минут: Vercel + Supabase Cloud

Пошагово — `docs/vercel.md`: один SQL-файл `supabase/setup-cloud.sql` в Supabase и импорт папки `web` в Vercel.

## Развернуть на своём сервере в РФ со ссылкой (5–10 минут)

1. Создайте виртуальную машину в Yandex Cloud или Selectel: Ubuntu 24.04, 2 vCPU, 4 ГБ RAM, диск 30 ГБ,
   публичный IP. Разрешите входящие порты 22, 80 и 443.
2. Подключитесь по SSH и выполните одну команду:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/LSETony/streamlit-example/claude/pensive-hawking-361iv6/deploy/install.sh | sudo bash -s -- --demo
   ```

3. Через 5–10 минут скрипт напечатает ссылку вида `https://app.<IP>.sslip.io` и демо-входы
   (`owner@demo.core` / `demo12345`). HTTPS-сертификат выпускается автоматически.

Свой домен: добавьте A-записи `app.<домен>` и `api.<домен>` на IP сервера и запустите скрипт с `--domain <домен>`.
Без `--demo` база будет пустой — первый владелец регистрируется на странице «Подключить зал».
Подробности (резервные копии, ЮKassa, SMS, push) — `docs/deploy.md`.

## Быстрый старт (локально)

Нужны Docker и Node.js 20+.

```bash
node deploy/keys.mjs > deploy/.env
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
docker exec -i core-db-1 psql -U supabase_admin -d postgres < supabase/seed.sql   # демо-зал «Атлет»

cd web
cp .env.example .env.local        # вписать ANON_KEY, SERVICE_ROLE_KEY и GYM_SECRETS_KEY из deploy/.env
npm ci && npm run dev             # http://localhost:3000
```

Демо-входы (пароль `demo12345`): `owner@demo.core` — владелец, `admin@demo.core` — администратор,
`reception@demo.core` — ресепшен, `team@demo.core` — команда core. (раздел «Залы»).
Приложение: телефон `+7 916 000-00-01`, SMS-код в локальной среде — `123456`.

Можно работать и через Supabase CLI (`supabase start` использует `supabase/config.toml`, миграции и `seed.sql`).

| 7 | Безопасность, 152-ФЗ, скорость | RLS на всех таблицах, деньги только через функции, ключи ЮKassa зашифрованы, service key только на сервере; self-hosted в РФ |

**Не входило в MVP и не делалось** (раздел 1): режим тренера, ИИ-функции, кампании, турникеты и 1С, несколько залов
в одном кабинете, витамины/InBody, когорты, публичный API, автоматический биллинг залов.

**Упрощения, которые стоит знать команде**

* Лист ожидания (FR-5.6, «желательно») не сделан.
* Двухфакторный вход для владельца (раздел 7, «желательно») включён в Auth (TOTP), но экрана подключения в кабинете пока нет.
* Статус абонемента `pending` добавлен к списку из ТЗ — это абонемент, который ждёт онлайн-оплаты.
* Логотип в интерфейсе — контуры шрифта Outfit 500, подобранного по присланной картинке (`web/public/brand/logo*.svg`,
  `web/components/logo.tsx`). Если есть исходный SVG от дизайнера — замените эти файлы.

## Проверки

| Что | Команда | Результат на стенде |
|---|---|---|
| SQL-тесты: изоляция залов (каждая таблица × каждая роль), бизнес-правила, гонка за последнее место | `supabase/tests/run_local.sh` (PostgreSQL 15+) | все зелёные |
| Нагрузка: 5 000 клиентов, 2 года истории, 650 тыс. визитов | `psql -f supabase/tests/perf/perf.sql` | дашборд 0,36 с · «зона риска» 0,7 с · QR 4 мс |
| Юнит-тесты кабинета (импорт, даты, QR-совместимость с сервером) | `cd web && npm test` | 13 тестов |
| Типы и линтер | `npm run typecheck && npm run lint`, `deno check` для функций | чисто |
| Сквозной сценарий на живом стенде | `node web/e2e/smoke.mjs` (переменные — в начале файла) | 14 шагов: QR → красный экран → продажа → зелёный, устаревший QR, новый клиент за ~2 с, импорт с ошибками, запись сверх вместимости, онлайн-оплата → webhook → повтор без эффекта, возврат через ЮKassa, права ролей |

Реальные платежи ЮKassa, отправка SMS/push и вход через Apple-устройства на стенде не проверялись (нужны
ключи зала и сертификаты): вместо ЮKassa использовалась имитация её API с тем же протоколом.

## Структура

```
supabase/
  migrations/        схема, RLS, бизнес-логика, аналитика
  functions/         Edge Functions: API /v1, ЮKassa, notify, maintenance, sms-hook
  tests/             SQL-тесты, нагрузочный тест, тест гонки
  seed.sql           демо-зал с историей за 10 месяцев
web/                 кабинет зала (Next.js)
deploy/              docker-compose для self-hosted Supabase, генератор ключей, миграции
docs/                openapi.yaml, mobile-app.md, deploy.md
```
